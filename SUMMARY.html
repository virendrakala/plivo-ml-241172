Architecture & Configuration

Our final winning model architecture maximizes the 2,000,000 parameter budget while accommodating a larger custom vocabulary:

  • Layers (n_layer): 4
  • Embedding Dimension (n_embd): 192
  • Attention Heads (n_head): 8
  • Context Window (block_size): 256 tokens
  • Vocabulary Size: 768 tokens (256 byte fallback + 512 BPE merges)
  • Weight Tying: Enabled (tie_weights = True), saving ~150k parameters by sharing the embedding and output projection layers.
  • Initialization: Scaled residual projections (GPT-2 style) with std = 0.02 / sqrt(2 * n_layer) for early training stability.

Training Optimizations

To squeeze maximum learning out of the strict 2,000 step budget, we made several aggressive changes to the training loop:

  • Optimizer: Switched from basic Adam to AdamW with a weight decay of 0.1 (excluding LayerNorm and bias terms) for better generalization.
  • Learning Rate Schedule: Replaced the constant LR with a Cosine Decay schedule (peak 2e-3, min 1e-4) and a 150-step linear warmup. The higher peak LR allowed us to converge much faster in the restricted step budget.
  • Batching: Increased batch size to 32 and added gradient accumulation (steps=2), yielding an effective batch size of 64.
  • Stability: Added gradient clipping (max_norm=1.0) to prevent early spikes.

The Tokenizer (The Biggest Win)

The provided corpus is heavily mixed with Hindi (Devanagari script). The baseline byte-level tokenizer translates each Devanagari character into 3 separate byte tokens. This devastated the 128-token context window and wasted parameters.

We trained a custom Byte-Pair Encoding (BPE) Tokenizer with 512 merges directly on the corpus. This compressed the training data from 7.3M bytes to 2.8M tokens (a 2.59x compression ratio), drastically increasing the effective context window and yielding the largest single improvement to our BPB score. It safely falls back to bytes for out-of-vocab characters, passing all round-trip evaluation tests.
